## 一、竞品拆解

### 1.1 一句话定位
**把任何视频 / 音频 / 链接（YouTube、TikTok、Facebook……）转成文字稿，再用 AI 做总结、笔记、翻译。** 免费、免注册即可用，靠额度限制转化付费。

### 1.2 流量结构（2026 年 9 月，全球）
- 月访问量约 **149 万**（首页 62.6 万 ≈ 42%）
- 渠道：搜索 56.8%、直接 32.8%、社交 4.3%、引荐 4.0%、邮件 1.2%，广告几乎为 0 → **纯 SEO 驱动**
- 按页面类型汇总（合并各语言版本）：

| 页面类型 | 月访问 | 说明 |
|---|---|---|
| 首页（各语言） | ~71 万 | 品牌词 + "video transcriber / transcribe video to text" |
| converter/youtube-to-mp4 | ~21.7 万 | 下载器，法/西/德/日语流量为主 |
| facebook-transcript-generator | ~13.4 万 | **82% 来自自然搜索，单页最强的转录类落地页** |
| converter/youtube-to-mp3 | ~11.4 万 | 下载器 |
| video-transcript-generator | ~7.7 万 | |
| tiktok-transcript-generator | ~4.6 万 | |
| video-to-text / youtube-to-transcript | ~6.1 万 | |
| youtube-subtitle-downloader | ~1.9 万 | |

**结论**：
1. 转录类落地页 + 多语言是流量主体；
2. YouTube 转 MP3/MP4 下载器约占 22% 流量，但有版权、DMCA、支付通道封号风险（见第七节）；
3. 长尾工具页（"xxx transcript generator"、"xxx to text"）是可规模化复制的 pSEO 模式。

### 1.3 关键词机会（Semrush US，1588 个词）
低 KD、竞品排名靠前的词值得优先做：

| 关键词 | 月搜索量 | KD | 备注 |
|---|---|---|---|
| tiktok transcript | 6,600 | 27 | KD 低 |
| tiktok transcript generator | 2,900 | 29 | KD 低 |
| transcrever video em texto | 2,400 | 26 | 葡语，KD 低 |

核心大词（video to text、transcribe video to text、video transcript generator）KD 都在 57–78，新站短期内拿不下，**靠长尾 + 多语言先起量**。

### 1.4 功能清单（竞品现状）
- 输入：本地上传（单文件最大 500MB / 付费 5GB）、YouTube 链接、TikTok / Facebook / Instagram / X / Bilibili 链接
- 转录：多语言、说话人识别、时间戳、两档精度（basic / advanced）、批量 5 个
- AI 后处理：总结、AI Notes、AI Chat、思维导图、信息图
- 翻译：字幕翻译 200+ 语言、AI 配音（Dubbing）
- 导出：TXT / SRT / DOCX、带字幕视频下载
- 其他：My Assets 历史记录、API & MCP、桌面客户端、Chrome 插件、博客、竞品对比页（vs HappyScribe / TurboScribe / Descript …）、11 种语言

## 二、产品决策（已定）

| 决策 | 内容 |
|---|---|
| 核心闭环 | 上传文件或贴链接 → 文字稿 → AI 总结 → 导出。先做竞品流量最大的这部分，不追求一次复刻全部功能 |
| 登录 | **转录必须登录**，不给匿名额度。未登录可浏览、上传、预览链接；点"转录"弹登录，登录回来自动提交（竞品要再点一次） |
| 语言 | 先做 `en`（默认，无前缀）+ `zh`（`/zh/...`）；中文审核通过后再扩其他语言 |
| 收款 | Dodo Payments（首选）→ PayPal → Waffo（备选） |
| AI 调用 | 统一 AI SDK v6，prompt 放 `prompts/` |
| 差异化 | 登录后自动继续；结果页有独立链接；转录完自动出 AI 总结；导出格式齐全 |

### 3.3 处理流程

```
[浏览器] 选文件 ──► POST /api/transcriptions/upload-url ──► 拿到 R2 预签名链接 ──► PUT 直传 R2
    │
    └─ 点"转录"（未登录 → 弹登录 → 回来自动继续）
          ▼
POST /api/transcriptions  { storageKey, fileName, durationSec, language }
  ├─ 校验登录、文件时长、积分是否够
  ├─ 事务内：建任务（status=pending）+ 扣积分（写 credit_ledger）
  └─ 返回 id，前端跳到 /t/[id]
          ▼
处理任务
  里程碑 1–2：Next.js after() 在同一个函数里异步跑（中小文件）
  里程碑 3 起：VPS Worker 轮询 pending 任务处理（链接下载、大文件压缩切片）
  ├─ 成功：写入 segments，status=done
  └─ 失败：status=failed + 错误原因，事务内退回积分（写 credit_ledger）
          ▼
/t/[id] 轮询 GET /api/transcriptions/[id] → 显示进度 → 文字稿 → 导出（前端直接从 segments 生成 TXT/SRT/VTT）
```

原则：转录或 AI 出错就把错误展示给用户并退回积分，不返回假结果。

### 3.4 积分与额度

- **1 积分 = 1 分钟基础转录**，按音频时长向上取整到分钟扣减；高级档以后按倍数扣。
- 扣减在建任务时预扣，失败全额退回。
- AI 总结随转录附带，不单独扣积分（成本低，先不收；以后的 Ask AI / 信息图另算）。
- 注册赠送积分：**一次性送 20 积分（= 20 分钟基础转录），不按天重置**。竞品是每天送 20 分钟，我们只送一次，试完效果就要付费；成本每人最多约 ¥0.09。

### 3.5 数据模型（在模板现有表基础上新增）

```
transcription
  id, user_id → user.id,
  source_type      'upload' | 'youtube' | 'tiktok' | ...
  source_url       链接任务的原始地址
  storage_key      R2 对象 key（上传任务）
  file_name, duration_sec, language, quality('basic'|'advanced'),
  status           'pending' | 'processing' | 'done' | 'failed'
  progress         0–100
  segments         jsonb：[{ startMs, endMs, speaker, text }]
  error_message, credits_charged,
  created_at, updated_at, deleted_at   ← 软删除

ai_summary（里程碑 2）
  id, transcription_id, template, locale, content, created_at
```

- 文字稿片段直接存 `segments` jsonb，不单独建表：读取和导出都是整篇处理，编辑时整体写回。
- 积分流水沿用 `credit_ledger`，新增 reason：`transcription_usage`、`transcription_refund`。
- 源文件 7 天后由定时任务删除，只保留文字稿。

1. **工具页矩阵**（第一批 15 个，按流量与 KD 排序）：
   `video-to-text`、`youtube-transcript-generator`、`youtube-to-transcript`、`tiktok-transcript-generator`、`facebook-transcript-generator`、`instagram-transcript-generator`、`video-transcript-generator`、`mp4-to-text`、`mp3-to-text`、`audio-to-text`、`video-to-srt`、`youtube-subtitle-downloader`、`video-summarizer`、`speaker-label-transcription`、`time-code-transcription`

2. **多语言**：
   - 第一阶段只做英语 + 简体中文。每个页面同时生成两版 → 你审中文 → 有问题中英同步改 → 定稿。

3. **每页内容**：首屏可直接用的工具框 + 3 步说明 + 功能点 + 使用场景 + FAQ（FAQPage schema）+ 相关工具内链。文案原创，不照搬竞品。
4. **竞品对比页**：TapeScript vs TurboScribe / HappyScribe / Descript / VideoTranscriber。
5. **博客**：模板已有 MDX 博客，写 "how to get transcript of youtube video" 这类教程。
6. **外链**：Product Hunt、AI 工具导航站、Reddit / Indie Hackers。

## 七、风险

1. **YouTube 下载器（转 MP3/MP4）不做**：竞品约 22% 流量来自这里，但有版权和 DMCA 风险，支付通道可能因此封号。
2. **YouTube 抓取稳定性**：反爬持续升级，yt-dlp 需常更新，代理是持续成本。
3. **滥用**：已强制登录，仍要防批量注册小号（同 IP 注册上限、邮箱注册加 Turnstile）。
4. **Groq 单文件大小限制**：上限未核实，M1 先支持中小文件，大文件到 M3 用 Worker 压缩切片。
5. **隐私合规**：源文件 7 天自动删除；隐私政策、条款、版权投诉页上线前更新为 TapeScript 内容。
6. **收款**：各平台对主体的审核要求未确认。

## 九、已知问题（暂缓，先做核心功能）

| # | 问题 | 位置 | 影响 | 处理计划 |
|---|---|---|---|---|
